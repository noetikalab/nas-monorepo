# 协议层

> 本知识库使用 4 种文章类型。Agent 创建/更新/检索知识时以此作为协议参考。

---

## 一、文章类型

按 Agent 的读取场景分类，不是按内容的主题分类：

| 类型 | Agent 读取时机 | 独特字段 |
|------|---------------|---------|
| 主题文档 | 理解项目、获取上下文 | 背景与目标 + 相关文章链 |
| 决策记录 | 做技术选型时参考 | 选项对比 + 理由 + 后果 |
| 坑点记录 | 编译失败/运行报错时 | 匹配关键词 + 现象→根因→修复→预防 |
| 契约文档 | 写代码时查接口 | 接口表格 + 数据模型 + 对接状态表 |

---

## 二、通用元数据头

每篇文章必须包含 4 行元数据：

```
> 时效：fresh | unverified / 上次验证：YYYY-MM-DD
> 标签：tag1, tag2, tag3
> 源材料：[链接/路径]
> 创建：YYYY-MM-DD / 更新：YYYY-MM-DD
```

## 三、时效规则

| 标签 | 含义 | Agent 行为 |
|------|------|-----------|
| `fresh` | 上次验证通过，且无关联代码变更 | 直接使用 |
| `unverified` | 新建未验证，或 git diff 检测到关联文件变更 | 使用前先验证关键声明，通过后改回 fresh |

git diff 是唯一的 staleness 触发源，高频开发场景下不需要 N 天阈值。

## 四、标记 unverified 的时机

1. **git commit 后**：提取 git diff → 匹配 index 标签 → 标记相关行 unverified
2. **用户声明**："后端改了 API"、"升级了依赖"

改回 fresh：Agent 使用 unverified 文章前 → 验证关键约束 → 通过则改回 fresh。

## 五、交叉引用格式

```
[[文件名]] 或 [[文件名#节标题]]
```

- 引用后跟"为什么相关"（一句话）
- **双向**：A 链 B 时 B 必须回链 A
- 所有交叉引用在文章末尾的"相关文章"节中

## 六、检索入口

wiki/index.md 是唯一检索入口。Agent 不打开文章前必须先读 index。

检索路径：index 摘要匹配 → 打开 → 读背景与目标 → 相关则深入，不相关关闭。

复杂问题（含 2+ 技术关键词）走 multi-match 模式：分别 grep 各关键词 → 合并同一文件的邻近命中 → 跨文件排序 → 返回根因+关联+诊断（~800 tokens）。
